# Methodology

Everything below is implemented in `ml/` and `backend/healthrisk_runtime/`. Numbers quoted come from
`reports/` and were generated by the pipeline. Re-running `python -m ml.train` regenerates them.

## 1. Problem framing

| Item | Decision |
|---|---|
| Unit of analysis | One inpatient **encounter** of a patient with diabetes |
| Prediction point | **At discharge** from the index encounter |
| Target `readmitted_30d` | `1` if raw `readmitted == "<30"`, else `0` (`">30"` or `"NO"`) |
| Positive-class prevalence (cohort) | 11.39% (imbalance ≈ 7.8 : 1) |

**Why binary `<30` vs. the rest?** The 30-day window is the standard used by readmission-reduction programmes
(for example the US CMS Hospital Readmissions Reduction Program). The `>30` class is a different outcome: a
later return that is less likely to reflect discharge planning. Merging `>30` with `NO` is a deliberate modelling
choice. It is not a claim that they are equivalent. One consequence is that the negative class is mixed, which
caps how well any model can separate the classes.

## 2. Cohort construction (`ml/data_ingestion.build_cohort`)

| Step | Rows removed | Reason |
|---|---|---|
| Duplicate `encounter_id` | 0 | Integrity check |
| Discharge disposition 11, 19, 20, 21 (expired) and 13, 14 (hospice) | 2,423 | These patients are not at risk of readmission. Labelling them "not readmitted" would teach the model that death means low risk. |
| `gender == "Unknown/Invalid"` | 3 | Invalid value |

Final cohort: **99,340 encounters from 69,987 patients**.

## 3. Leakage prevention

| Risk | Mitigation |
|---|---|
| Target in features | `readmitted` and `readmitted_30d` are excluded. A test asserts that no excluded column reaches the features. |
| Identifiers | `encounter_id` and `patient_nbr` are never features. `patient_nbr` is used only as the grouping key. |
| **Same patient in train and test** | 46% of encounters belong to patients with several encounters. All splits use `StratifiedGroupKFold` grouped by `patient_nbr`: the hold-out test set (1/5 of patients) and the 3-fold CV inside training. Patient overlap is asserted to be 0. |
| Preprocessing fitted on all data | Imputation, scaling and one-hot vocabularies sit inside an sklearn `Pipeline` and are fitted on training folds only. Feature engineering is stateless (per-row, no learned statistics). |
| Future information | Every input exists at discharge: demographics, admission details, length of stay, labs and procedures during the stay, medications and changes during the stay, diagnoses, and the count of visits in the **prior** year. |
| Calibration / threshold tuned on test | Platt scaling and the decision threshold are fitted on **out-of-fold training predictions**. The test set is used once, for final reporting. |
| Model selection on test | The selection rule uses CV PR-AUC only. Test metrics are reported for every model but never used to choose. |

### Excluded columns

| Column | Reason |
|---|---|
| `readmitted` | Original outcome (direct leakage) |
| `encounter_id` | Row identifier; may encode time order |
| `patient_nbr` | Patient identifier (grouping key only) |
| `weight` | 96.9% missing |
| `payer_code` | 39.6% missing; insurance is a socioeconomic proxy, not a clinical factor |
| `race` | Sensitive attribute. Kept out of the model and used only for the subgroup fairness audit. |
| `examide`, `citoglipton` | Constant columns |

## 4. Feature engineering (`backend/healthrisk_runtime/features.py`)

A single pure-Python function, `engineer_record`, is used for both training and inference, so the two cannot diverge.

| Feature | Definition | Rationale |
|---|---|---|
| `age_years` | Midpoint of the 10-year age bracket | Ordinal age |
| `total_prior_visits` | outpatient + emergency + inpatient visits (prior year) | Overall healthcare utilisation |
| `any_prior_inpatient` | 1 if any inpatient stay in the prior year | Strongest single signal in the EDA |
| `meds_per_day` | `num_medications / time_in_hospital` | Medication burden relative to stay |
| `n_diabetes_meds` | Number of the 23 diabetes drugs not equal to "No" | Treatment complexity |
| `n_med_dose_changes` | Number of diabetes drugs with dose Up or Down | Treatment instability |
| `insulin_treated`, `on_diabetes_med` | Indicators | Treatment intensity |
| `a1c_tested`, `glucose_tested` | Whether the test was performed | Testing itself is informative (Strack et al., 2014) |
| `diag_{1,2,3}_group` | ICD-9 chapter (Circulatory, Respiratory, Digestive, Diabetes, Injury, Musculoskeletal, Genitourinary, Neoplasms, Other, Missing) | Reduces about 700 codes to clinically meaningful groups |
| `los_category` | 1–2, 3–6, 7+ days | Non-linear length-of-stay effect |
| `admission_type`, `discharge_disposition`, `admission_source` | ID mapped to label using `IDS_mapping.csv` | Interpretability |

## 5. Preprocessing (`ml/preprocessing.py`)

- **Numeric** (18 features): `SimpleImputer(median)` → `StandardScaler`.
- **Categorical** (14 features): `SimpleImputer(constant="Missing")` → `OneHotEncoder(min_frequency=100, handle_unknown="infrequent_if_exist")`.
  Rare categories (fewer than 100 training rows) are pooled. Categories never seen in training are mapped to the
  same infrequent column at inference, so inference never fails on a new value.
- The output is 124 model columns.

## 6. Models and tuning (`ml/train.py`)

All five models share the preprocessor, the patient-grouped 3-fold CV and the random seed (42). `RandomizedSearchCV`
optimises **average precision (PR-AUC)**.

| Model | Search space (abridged) | Imbalance handling |
|---|---|---|
| Logistic Regression | C ∈ log-uniform(1e-3, 3) | `class_weight ∈ {None, balanced}` |
| Decision Tree | depth 3–10, min leaf 20–400, gini/entropy | `class_weight ∈ {None, balanced}` |
| Random Forest | 150–200 trees, depth 6–10, min leaf 20–100 | `class_weight ∈ {None, balanced_subsample}` |
| Gradient Boosting | 150–250 trees, lr 0.05–0.1, depth 2–4, subsample 0.7 | none (threshold handles it) |
| XGBoost | 200–600 trees, lr, depth 3–5, child weight, subsampling, L2 | `scale_pos_weight ∈ {1, √r, r}` |

**Why no SMOTE?** Resampling distorts predicted probabilities, and synthetic minority samples drawn from mixed
categorical data are hard to justify clinically. The prevalence is 11%, which is low but not extreme. Class weighting
is tested as a tuned option, and the operating point is chosen by threshold, which addresses the same goal
transparently.

**Selection rule:** highest mean CV PR-AUC. Ties within 0.002 are broken by higher ROC-AUC, then lower Brier score.

## 7. Calibration and threshold

- **Platt scaling**: a logistic fit of the out-of-fold score (log-odds) against the label, fitted on training
  out-of-fold predictions. The deployed probability is `sigmoid(a·score + b)`.
- **Decision threshold**: maximises F2 (recall weighted twice as much as precision) on the calibrated out-of-fold
  predictions, subject to flagging **at most 40%** of encounters, because follow-up capacity is finite. Result: **0.110**.
- **Risk bands** (configurable in `ml/training_config.json`): Low < 0.10 ≤ Moderate < 0.20 ≤ High. On the test set
  the observed readmission rates are 6.9%, 13.7% and 27.0% respectively.

## 8. Results (held-out test set: 19,867 encounters / 13,951 patients)

| Model | CV PR-AUC | Test PR-AUC | Test ROC-AUC | Recall @ thr | Precision @ thr |
|---|---|---|---|---|---|
| **Gradient Boosting (selected)** | 0.2265 ± 0.0071 | 0.2310 | 0.6662 | 0.618 | 0.177 |
| XGBoost | 0.2251 ± 0.0058 | 0.2268 | 0.6651 | 0.594 | 0.182 |
| Random Forest | 0.2220 ± 0.0060 | 0.2225 | 0.6607 | 0.597 | 0.177 |
| Logistic Regression | 0.2119 ± 0.0083 | 0.2192 | 0.6610 | 0.593 | 0.177 |
| Decision Tree | 0.1999 ± 0.0047 | 0.2018 | 0.6462 | 0.574 | 0.173 |

Selected model details: specificity 0.631, F1 0.275, Brier 0.0960, ECE 0.0057, and 39.7% of encounters flagged.
Full report: `reports/evaluation/evaluation_report.md`.

**How to read these numbers:**

- Discrimination is modest. ROC-AUC is about 0.67, which is in line with published results on this dataset.
- PR-AUC is roughly twice the no-skill baseline (0.114).
- The top three models differ by less than one CV standard deviation, so the ranking among them is not robust.
- Precision of about 18% means roughly 4–5 alerts per true readmission at this threshold.

None of this establishes clinical usefulness.

## 9. Explainability

- **Global**: `shap.TreeExplainer` on 2,000 test encounters. One-hot SHAP values are summed back to their source feature.
  The top drivers are discharge disposition, prior inpatient admissions, total prior visits, number of diagnoses and
  primary diagnosis group. Permutation importance (drop in PR-AUC) is reported as a model-agnostic cross-check.
- **Per prediction**: exact path-dependent **TreeSHAP**, implemented in pure Python in `engine.py` and verified
  against the `shap` library in `tests/test_ml.py` (absolute tolerance 1e-5). Contributions are reported in
  calibrated log-odds and sum exactly to the prediction.
- SHAP values describe **associations the model learned**, not causal effects.

## 10. Fairness audit

Test-set ROC-AUC and recall are reported by gender, age bracket and race. Race is not a model input. Gender is
similar (ROC-AUC 0.665 vs 0.667). Smaller subgroups show wider variation that is partly sampling noise. See
`evaluation.subgroups` in the evaluation report.

## 11. Monitoring

PSI per feature is computed against training-set reference distributions:

- **Held-out test set**: all PSI < 0.001, as expected for a random patient split.
- **Latest 20% of encounters** (`encounter_id` order used as a proxy for time): moderate shifts in discharge
  disposition (0.21), number of diagnoses (0.16) and admission source (0.15). This is consistent with known coding
  changes over the 1999–2008 period, and shows why drift monitoring matters before any prospective use.

No outcome labels are collected after deployment, so live performance is **not** monitored.
